# 模型可学习特征分层规范

## 我们当前是怎么进行标注的？

产品输出需求 → 测试理解需求，开始构造标注模板 → 和产品、开发达成共识（主要是最终是否通过的指标）→ 开始标注。

但是在这里，我们的业务需求和模型可识别的标注其实是混合的。

## 问题：人认为重要的标签 ≠ 模型能可靠输出的标签

以下来自我们实际模板 + 20 组真实图片的 pipeline 评估结果，每个例子说明一种错位类型。

### 例 1：离散模糊度 — 人类语义，模型不可学习

```
模板设计：blur → single_select {clear, slight, heavy}
模型输出：clear, slight, heavy 随机猜
准确率：36.8%
```

人的直觉："轻微模糊"和"严重模糊"有清晰边界。

模型看到的 reality：blur 是连续像素值。同一张图，光照变化 10%，Laplacian 方差从 0.45 变到 0.52，但人的标签仍然都是"clear"。模型学不到"边界在哪里"。

→ **应该改为：blur_score = numeric (0.0-1.0)，OpenCV 直接测量，业务侧定阈值。**

### 例 2：多选目标类型 — 人习惯"列举所有可能"，模型需要"唯一答案"

```
模板设计：object_type → multi_select {cardboard_box, envelope, poly_mailer, bag, ...}
模型输出：总在列举 2-3 个
准确率：50.0%
```

人的直觉："画面中地上是纸箱、手上是购物袋" → 选两个。

模型训练需要的 reality：一个目标只有一个正确标签。多选导致训练信号不一致 — 同一张图标注为 {cardboard_box, bag}，模型不知道该学哪个。

→ **multi_select 适合人做标注，不适合模型做推理。核心分类属性应优先用 single_select。**

### 例 3：可观测性用"判断"代替"测量"

```
模板设计：occlusion → single_select {none, partial, heavy}
          lighting → single_select {normal, dim, harsh}
准确率：occlusion 47.4%, lighting 57.9%
```

人的直觉：人能"看出来"遮挡程度和光照条件。

模型处理方式：遮挡 = 边缘连续性丢失率；光照 = 直方图均值。这些都是**可以精确计算的物理量**，不需要大模型"判断"。

→ **可观测性属性不应走 LLM，应由 OpenCV 出连续分，人在业务侧定义阈值。**

### 例 4：模型并不能理解什么是场景

```
“快递员正在放包裹”、“居民购物回家”
```

人看到这个场景是：**看图 → 结合生活经验 → 推理语义 → 得出结论**

模型看到这个场景是：**pixels → feature embedding → statistical pattern**

模型并不知道：

- “投递”
- “收件”
- “居民”
- “意图”

这些抽象语义。



但是人是用了：

* 动作理解
* 场景知识
* 社会经验
* 时序脑补





## 什么是有效标注？

当我们拿到产品给出的需求，我们要做拆解，把需求中的每个字段按以下分层归类：

### 第一层：Object Core Features（核心对象特征）

模型可以**明确看到**的属性。特征是对象的物理实在。

```
object_shape, object_material, has_tape,
corner_visibility, surface_texture,
box_integrity, deformation
```

→ 走 **per-candidate + Gemini**，参与模型训练。
→ 精度不够时，优先检查标注一致性，而非换模型。

### 第二层：Visibility（可见性）

**可精确测量**的物理量，不是"判断"。

```
blur, occlusion, cropped, small_object,
lighting, shadow_strength
```

→ 走 **OpenCV 连续量输出**，不走 LLM。
→ 业务侧定义阈值，而不是让模型猜"轻微还是严重"。

### 第三层：Confusion Factors（混淆因素）

**守卫性质**的布尔值。特征是"这个看起来像但不是"。

```
similar_objects_nearby, background_clutter,
bag_like_shape, wooden_box_confusion
```

→ 走 **Gemini 场景级分析**，用于 reject 低置信候选。
→ 不参与正向训练，只做过滤。

### 第四层：Scene Semantics（场景语义）— 弱化

模型不具备理解这些抽象语义的能力。

```
delivery_scene, indoor_outdoor,
doorstep, human_present
```

→ 不走 per-candidate，不走主线 pipeline。
→ 作为 Metadata Layer，仅用于 dashboard / error analysis / retrieval。

### 总结：两层标注体系

```
Trainable Features（Ground Truth Layer）
├── Layer 1: Object Core → 监督模型的训练信号
├── Layer 2: Visibility → 辅助模型的测量信号
└── Layer 3: Confusion → 模型的过滤守卫

Analytics Features（Metadata Layer）
└── Layer 4: Scene Semantics → 只分析，不训练
```



# 好标签：

必须满足：

| 条件   | 含义               |
| ------ | ------------------ |
| 可观测 | 能从像素稳定看出来 |
| 可重复 | 不同人标结果接近   |
| 可学习 | 模型能形成稳定特征 |
| 可收敛 | Eval 能提升        |
| 可泛化 | 新数据仍成立       |

------

# 坏标签：

通常是：

| 类型     | 问题             |
| -------- | ---------------- |
| 主观语义 | “像不像正在配送” |
| 意图推理 | “是不是刚放下”   |
| 场景脑补 | “居民正在收件”   |
| 人类经验 | “看起来像...”    |
